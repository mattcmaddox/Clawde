# Unfinished-Feature Audit & Completion Plan

**Date:** 2026-08-28
**Method:** code-first audit (not doc-first). Every item below was confirmed against
actual call sites / feature-flag wiring / git history. Generated by the unwired-code scanner
at `scripts/audits/unwired-code-scan.py`.

## TL;DR

Clawde is a Rust port of the TypeScript Claude Code / opencode codebase. Two bulk commits —
`40717b8 "rust port overhaul"` and `d799f70 "feat: implement automated agent improvements"` —
carried over **whole modules wholesale** ("Port of `src/…/index.ts`", "mirrors `src/…/*.ts`").
Many of those modules were ported **without their integration**, so they compile today but are
unreachable. They are the **outlines of planned features that got lost in the port** — not rot.

Crucially, nearly all of the ported cloud-facing modules tie to a backend Clawde no longer uses
`api.claude.ai` / `api.anthropic.com` / `GrowthBook` / `claude.ai` WebSocket). Clawde's real
cloud surface is **Clawde Desktop via the `bridge` crate**. So even wanted features need a
**backend rebind**, not a straight wire-up.

This document is in three parts:
1. **Inventory** — every unwired/ported item, classified.
2. **Plan** — how to finish the *intended* features, with fresh ideas from current AI research
   (Anthropic context engineering, A-MEM agentic memory, progressive disclosure).
3. **Already-removed** — the obvious non-feature dead code we deleted.

## Part 2 — Completion plan

### Principle

Thematically these cluster into **context/memory engineering** (part 2 below) and **cloud
session surface** (part 3). Part 3 requires a product decision because it targets a backend that
doesn't exist for this fork. Part 2 is pure quality work that closes real gaps and no decision is
needed — recommended to ship first.

### (REVISED 2026-08-28 after grounding in call sites)

**Correction loop and context-refresh are ALREADY fully wired — this section over-claimed.**
- Correction auto-memory runs every turn at `query/src/lib.rs:2143` (detect → extract → save).
  `process_correction` is a **redundant duplicate**, not a missing feature.
- Context-refresh is fully wired at `query/src/lib.rs:2094-2119` (detect external edit → refresh
  → status event → inject system message). The dead `watch_file`/`check_for_changes`/
  `process_context_refresh` helpers are redundant duplicates.

**Action:** delete the redundant duplicates (`process_correction`, `context_refresh` dead fns)
and remove this section's build-the-loop framing.

## 2.1 (REMOVED) correction-feedback loop — see revision above

- **Research basis (retained as reference):** Anthropic *Effective Context Engineering* (structured
note-taking / agentic memory) and A-MEM (agentic memory with link + evolution). Useful if/when the
storage format is upgraded to structured notes; see 2.3a.

### 2.2 (REVISED) context-refresh — already live; delete redundant helpers

The loop at `query/src/lib.rs:2094-2119` already realises the just-in-time pattern: it tracks
path+mtime, re-reads on change, and injects a system message. **Nothing to build here.**

**Fresh idea for a future enhancement (not needed to ship):** the injectable delta could carry
the changed regions rather than the whole file, matching Anthropic's "load on demand / keep it
tight" guidance more aggressively. Low priority — the current whole-file refresh is fine.

### 2.3 Wire the micro-compact effort + memory extraction

- `micro_compact_if_needed` runs `summarise_head(..., None, ...)` (no effort override). Thread the
  session's `QueryConfig.effort` through so micro-compaction honours user intent.
- Connect `compact_with_memory_extraction` into resume-time compaction (`compact_on_resume` is
  already called from `cli/src/main.rs:3273`). This delivers A-MEM-style "extract trumps
  summarise" — before discarding history, pull durable facts into memory.

### 2.4 Session-end teardown (small, fixes a real leak)

- Wire a session-end hook (on `/clear` clean-session exit, and normal shutdown) that calls
  `clear_session_shell_state(session_id)` and `clear_session_shadow(working_dir)` in
  `tools/src/lib.rs`, and drains + kills `REPL_SESSIONS` for the ending session per the existing
  `repl_tool.rs:44` note. This unblocks `clear_session_*` and REPL teardown at once.

### 2.5 Progressive disclosure for tools: finish `advanced()` (Phase 2, blocked)

- Goal (matches Anthropic *Equipping Agents / progressive disclosure*): omit `advanced()` tools
  from the initial `tools` array; surface them via a lightweight "available on request" hint and
  load on demand through the existing `ToolSearch` / `coordinator::filter_tools_for_mode`.
- **Blocker:** the active-tool-set tracking refactor in `run_query_loop`. Do not force — land the
  tracking first, then make `all_tools()` callers filter on `advanced()`.
- **Design note:** two-level disclosure (metadata hint in prompt always; body/tool-definition
  loaded only when relevant) is the established pattern. Keep `bundled_skills.rs` aligned — skills
  already use the same two-level shape (`SKILL.md` frontmatter then body), so unify the mechanism.

### 2.6 Auto-verify after edit (smallest-scope execution gap)

- `run_verify_after_edit` is implemented but never invoked from the loop. Wire it as an opt-in
  (feature-flag-gated via the existing `verification_agent` gate) continuation policy alongside
  the existing verify/decide machinery. Research basis: reflection loops — a separate rubric-check
  pass improves reliability; Clawde's existing `verify.rs` / `verify_container.rs` already models this.

## Part 3 — Cloud/session surface: DECIDED (2026-08-28, user)

**User decision:** no Anthropic-cloud sync is wanted. The user is open to *self-hosted* sync but
(per their own words) the code for that restructuring isn't worth writing — so **remove the cloud
code and move on.** The `api.claude.ai` / GrowthBook ports cannot be pointed at a self-hosted
server without significant rewriting, so they were removed rather than rebound.

The local env-var mechanism `core/src/feature_gates.rs` (which already replaces GrowthBook) is
kept and is the supported path for anyone self-managing flags.
